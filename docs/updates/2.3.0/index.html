Version 2.3.0

This update makes receiving-location reconciliation smarter by using actual Infor Visual transfer history, gives the review window clearer evidence for each proposed destination, and updates package quantity labels so they match the material unit of measure.

Highlights

What stands out in this release

Reconciliation follows real transfer moves

When a saved receiving row needs a location check, the app now uses Infor Visual transfer history around that receipt date to find the destination the material actually moved into.

Review decisions are easier to verify

The review window now shows transfer evidence such as Visual user, transfer time, transfer count, source locations, and why a destination was chosen before you save the change.

Per-package values use the material UOM

Package-level quantity displays now use the item unit of measure, so screens no longer imply that every per-package value is a weight in pounds.

What changed

Details by area

Receiving reconciliation now allocates rows from transfer-backed destination buckets

The app groups same-day receipt rows by material, reads related Infor Visual transfer movements, follows chained moves through staging locations, and only proposes a new destination when confirmed transfer quantity fully supports that saved row.

The review dialog now explains why a destination was selected

Each review item now shows the Infor Visual user, transfer date and time, the number of transfers considered, the source locations involved, and a plain-language explanation in the new “Why This Destination Was Chosen” section.

Rows without enough evidence stay in manual review instead of being forced through

If transfer evidence nets to zero, only points to ignored destinations, or cannot safely cover the full saved quantity, the row stays unresolved for manual attention instead of being saved with a weak guess.

Package quantity labels now reflect the item unit of measure

Manual Entry, Edit Mode, and the package selection cards now use “UOM/Pkg” style labeling and show the package value with the item unit of measure. Recommended-location messaging was also tightened so it only promises locations with positive on-hand quantity.

Why it matters

What this means in practice

Less guesswork during reconciliation

Operators can review suggested location changes against real transfer evidence instead of trying to infer where material likely ended up.

Safer save decisions

Rows with incomplete or conflicting evidence are left in Needs Attention, which reduces the chance of saving a location change that the transfer history does not fully support.

Clearer package quantities

When material is measured in something other than pounds, the per-package value is now labeled in a way that matches the actual item unit shown elsewhere in the workflow.

What you need to do

No action required

No action is required after this update. The new reconciliation logic and package-unit labels take effect automatically after the new version is installed.

  • If the reconciliation review window opens, check the new evidence panel before saving a suggested location change.
  • Look for “UOM/Pkg” anywhere package-level quantity is shown in Receiving.
  • If a row still appears under Needs Attention, continue using the normal manual review process for that row.

Need help?

Questions about reconciliation or package quantities?

If you need help after this update, share the version number shown at the top of this page (2.3.0) with your supervisor or the MTM IT support team. That helps them confirm you are on the release that introduced transfer-based reconciliation evidence and the updated package-unit labeling.
