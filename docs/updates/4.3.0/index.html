MTM Receiving Application

Version 4.3.0

This release makes the Guided Receiving steps faster to work through. Every step now starts with the cursor in the field you need next, and a purchase order with a single part number moves ahead on its own. Package count boxes open empty so Auto-Fill can copy counts down the grid, Scanner access is now managed from Settings instead of being fixed to a short list of accounts, and several everyday annoyances are fixed - deleting receiving history no longer reports a false error, lookups no longer spin forever when the ERP is slow, and windows open maximized on the right page.

Highlights

What is new in 4.3.0

Guided Receiving keeps you on track

All seven steps now place the cursor in the field you need next, and the PO Number is selected for you so you can type straight over it. A purchase order with one part number continues to the next step by itself.

Scanner access is now managed

An administrator can choose who may use Scanner from Core Settings, and the list applies to every workstation at once. The Scanner button and its keyboard shortcut only appear for people on the list.

Package counts start blank

Count boxes open empty instead of showing 1, so Auto-Fill can copy a count down the grid. The EA per Package figure updates as you type instead of waiting for you to leave the box.

What changed

Details of this release

Guided Receiving focuses the right field at every step

Each step of the guided workflow now places the cursor where you need it, no matter how you arrived on the page - pressing Next or Back, being moved ahead automatically, using the search bar, or picking the mode from the start screen.

The PO Number box is focused with its text already selected, so typing a new number replaces the old one. Load Information focuses the Number of Labels box, Weight & Quantity, Heat & Lot, and Package Type each focus the first row, Review & Save focuses the Save to Database button, and the final step focuses Start New Entry.

The Review and Complete steps previously had no focus target at all, so they did nothing until you clicked. If a field is not ready yet when the page opens, the application now keeps trying instead of quietly giving up.

Simple purchase orders move ahead on their own

The PO now loads as soon as you press Enter or leave the PO Number box, so the Load PO button is no longer required for everyday entry.

A purchase order that returns no part numbers is rejected outright. A warning appears in the header, the loaded PO details are cleared, the PO Number box is emptied, and the cursor returns there so you can try again.

A purchase order with exactly one part number selects that part for you, announces it in the header, and continues straight to Load Information. If your PO covers several part numbers, the parts list still appears and you choose as before. When the single part is on quality hold and you have not acknowledged it, the workflow stays on the PO step rather than moving on.

Step cards show the PO number and clearer headings

The Part Number and Description headings on the Load Information, Weight, Heat, and Package Type steps now include the PO Number, separated by a thin divider line. The PO segment stays hidden when there is no PO on the load.

Headings were tidied at the same time: Number of Loads (1-99) now reads Number of Labels (1-99), the Loads: label on the Weight step reads Labels:, and the Package Type heading is now simply Package Type: with the package type row moved below the divider.

Package counts start blank and Auto-Fill fills the gaps

Assigning a part number no longer puts a 1 in every package count box, so the boxes open empty and there is something for Auto-Fill to fill. Auto-Fill copies a count from the rows above into any box you left blank.

If you still leave rows blank when you leave the step, each blank row counts as a single package exactly as it did before, so the saved result is unchanged. The EA per Package figure now recalculates while you type rather than when you press Enter or click away.

WIP added to dunnage inventory options

When you add a new dunnage part or edit an existing one, the inventory type list now includes WIP alongside Not Inventoried, Adjust In, Receive In, and Both. Use it to flag dunnage that is consumed by work in progress rather than received into stock. The choice is shown on the part details card, the review step, and in saved history.

Scanner access list in Core Settings

Scanner access is decided by a single plant-wide list of employee numbers that an administrator maintains from the new Scanner Access card in Core Settings. The change takes effect for everyone at once, and access is re-checked when someone opens Scanner, so a freshly saved change applies immediately.

Until the list is saved, Scanner stays limited to the developer accounts it was restricted to before, so nothing changes for the floor until an administrator fills the list in. If the setting cannot be read, the application falls back to that same rule and never widens access by accident.

Material Availability Board fields expand or collapse together

The Material Availability Board field settings page gained Expand all and Collapse all buttons so every configurable row can be opened at once instead of one group at a time.

Welded Coils list cleaned up

Every part in the Welded Coils tool used to appear twice or more because the table itself held duplicate rows - 32 rows covering only 15 distinct part numbers. The surplus rows have been removed and a database rule now prevents new duplicates from being created, so the list shows each part once.

Each row now has its own Delete button, which removes that single part without disturbing the rest of the list. The previous Activate and Deactivate buttons are gone.

Deleting receiving history no longer reports a false error

Removing loads from Receiving Edit Mode sometimes failed with "Failed to save receiving data" even though the selected rows had in fact been deleted. The application misread the database's reply as "no matching row".

Deleting now checks whether the row is genuinely still present before reporting a problem, so a successful delete completes quietly. The same guard already used elsewhere in Receiving is now applied to this delete path.

Windows open maximized, on the right page, in the right theme

Top-level windows now open maximized, which covers the main window, the Settings window, the Volvo shipment history detail window, and the shared icon selector.

The main window was briefly visible during startup while it switched from the default theme to your saved theme, and it sometimes landed on the empty Dashboard placeholder instead of the Receiving mode selection page. Both are corrected: the window stays hidden until it is activated and is maximized in the same moment, so it never appears at the wrong size or theme, and startup navigation always runs.

Opening Ship/Rec Tools, or choosing a tool card inside it, no longer resizes the main window.

Part and location lookups no longer spin forever

When a lookup had to wait on Infor Visual, the progress indicator could spin indefinitely with no explanation, and losing focus, pressing Enter, or the page validating behind the scenes could all start the same lookup at once.

Overlapping lookups are now ignored so only one runs at a time. If the ERP does not answer within 20 seconds, the wait ends with a clear message telling you to check the ERP connection and try again, rather than leaving the screen stuck.

Why it matters

What this means on the floor

Fewer clicks per load

The cursor is already where you need it, Auto-Fill has blank boxes to work with, and a single-part purchase order moves ahead without you choosing the part or pressing Load PO.

Clear messages instead of dead ends

A purchase order with no parts tells you so and puts you back on the PO box, a slow lookup explains itself instead of spinning, and a completed history delete stops reporting a false failure.

Access you can control

Who may use Scanner is now a setting your administrator can maintain, instead of a fixed list of accounts, and the Welded Coils list finally shows each part once.

What you need to do

Pick up where you left off

No migration or setup step is required.

  • There is nothing to configure after this update - your preferences and saved work carry over, and previously saved receiving and dunnage records are unchanged.
  • Regular operators do not need to do anything and continue using the same screens.
  • Administrators: to give someone Scanner access, open Core Settings and use the Scanner Access card. Until the list is saved, Scanner remains limited to the developer accounts it was restricted to before.

Need help?

Reporting a problem

If a Guided Receiving step does not put the cursor where you expect, a package count does not fill in, Scanner is missing from your navigation bar, or a lookup reports a timeout, contact your supervisor or the MTM IT support team and include the version number shown at the top of this page.
