Personalized Label Locations

Each user can now set their own label file locations for all four label types, replacing the previous application-wide settings.

Version 2.7.0 Released January 2025

On this page

Highlights What changed Why it matters What you need to do Need help?

Version 2.7.0 introduces user-specific label file locations for better flexibility in multi-user workstations.

Highlights

Key improvements in this release

Personal label paths

Each user can now configure their own label file locations instead of sharing one set of paths across the entire application.

All four labels supported

User-specific settings are available for Receiving Label, Mini-Receiving Label, Volvo Label, and Dunnage Label.

One-time setup required

After updating, you'll need to configure your label file locations in the settings pages for each module you use.

What changed

Technical details

User-scoped label settings

Label file paths are now stored per user in the database instead of as application-wide settings. This means:

  • Each user can point to different label files based on their workstation or preference
  • Switching users on a shared workstation will automatically use that user's configured paths
  • Label settings are now found in the module-specific settings pages (Receiving, Dunnage, Volvo)
Settings page updates

The label path configuration pages in Settings have been updated to save your personal preferences instead of system-wide settings. Your saved paths will only apply when you're logged in.

Label button behavior

The four label buttons in the main window footer continue to work the same way, but now they open the label files you've personally configured rather than a shared application setting.

Why it matters

Benefits for your workflow

Multi-user workstations

If you share a workstation with other users, you can now each maintain your own label file locations without overwriting each other's settings. This is especially helpful when different users work with different label templates or file servers.

Personal preferences

You can customize label paths to match your specific workflow, network drive mappings, or local file structure without affecting other users.

Easier troubleshooting

When a label fails to open, IT can quickly check whether the issue is with your personal settings or a system-wide problem, making support faster and more targeted.

What you need to do

Required setup after update

⚠️ Action required

After this update is installed, you must configure your label file paths in the settings pages before you can use the label buttons.

Setup steps

  1. Click the Settings icon in the navigation menu
  2. Navigate to Receiving Settings and open Label Paths
  3. Enter the full file paths for:
    • Receiving Label (e.g., \\server\labels\receiving.lbl)
    • Mini-Receiving Label (e.g., \\server\labels\mini-receiving.lbl)
  4. Click Save
  5. Repeat for Dunnage Settings → Label Paths if you use dunnage labels
  6. Repeat for Volvo Settings → Label Paths if you use Volvo labels

First time opening a label

If you click a label button before configuring the path, the application will redirect you to the appropriate settings page automatically. Just enter your path and try again.

Need your old paths?

Contact IT or your supervisor to get the standard label file paths for your workstation. The previous application-wide settings are no longer used after this update.

Need help?

Support resources

If you have questions about this update or need assistance configuring your label paths:

  • Contact IT Support for help locating your label files on the network
  • Ask your supervisor for the standard label file paths used in your department
  • Check the in-app help documentation (press F1 or click the Help icon)

ℹ️ For IT and support staff

User label paths are stored in the settings_core_user database table under categories:

  • Receiving.UserLabels
  • Dunnage.UserLabels
  • Volvo.UserLabels
