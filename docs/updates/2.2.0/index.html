Highlights

What stands out in this release

Open labels from the shell footer

Receiving, Mini-Receiving, Volvo, and Dunnage label shortcuts are now grouped in the shared left-side footer so they stay available even when you move between modules or open settings.

Dunnage images stay closer to the app

The app now mirrors supported Dunnage images into a local cache at startup, which helps previews load more smoothly when the shared image folder is slow to respond.

Safer update publishing

The publish tool can automatically migrate a successful staged build to the shared deployment folder and blocks accidental close actions while work is still in progress.

What changed

Details by area

Label shortcuts moved into the shared MainWindow footer

The label buttons that were previously split across individual Receiving, Dunnage, and Volvo pages are now grouped together in the shared shell footer. This keeps the same labels one click away while you move between workflows and settings pages, and the app still redirects you to the correct settings page if a label path or LabelView executable is missing.

Dunnage image previews now prefer a refreshed local cache

At startup, the app refreshes a local Dunnage image cache from the configured shared image folder and uses that cached copy first when it displays preview images. Temporary files are kept out of the sync, stale cached images are removed automatically, and shared-folder changes are picked up again on the next startup.

Publish tool can automatically migrate staged output to the shared drive

After a successful publish, the deployment tool can now move the staged output into the selected shared-drive target automatically. It disables the publish and close controls while publish or migration is still running, shows clearer progress, and leaves the staged output behind only when automatic migration is turned off or cannot start.

Image assets are explicitly copied into build and publish output

The application project now marks common image file types to be copied into both normal build output and published output. That helps the local Dunnage image cache and shared shell label icons remain available after deployment.

Why it matters

What this means in practice

Less hunting for labels

Operators and supervisors can reach the most common label templates from one consistent location instead of remembering which workflow footer contains which button.

More reliable Dunnage previews

When the network share is busy or slow, the app can still show locally cached Dunnage images quickly, which makes maintenance screens and workflow previews feel more responsive.

Cleaner update handoff

Support staff get a clearer publish path with automatic migration, progress feedback, and better protection against closing the tool mid-deployment.

What you need to do

No action required

No action is required after this update. The shared label shortcuts and Dunnage image-cache behavior take effect automatically after the new version is installed.

  • If you use label templates regularly, look for the new shortcut buttons in the shared left-side footer above Settings.
  • If a label does not open, the app will guide you to the matching settings page so the LabelView path or label file can be corrected.
  • If Dunnage images still look out of date after deployment, restart the application so the startup sync can refresh the local cache from the shared image folder.
