Highlights

What is new in 4.6.0

Analytics that report our own work

Receiving Analytics now opens with two tabs. ERP Data is the page you already know and is unchanged. App Data is new: it reads our own completed receipts and answers how busy the dock was, whether we were on time, which suppliers fill it, and how much of the real work the app captures.

One panel per page

App Data shows Activity, On Time, Suppliers and Coverage as four pages behind a row of tabs, with the date range and filters sitting above them. One panel fills the screen at a time, so nothing is squeezed or scrolled.

Edit Mode Batch filter

Edit Mode has a new Batch list. Pick a batch and the grid shows only the skids that were entered together for that one part, so a correction stays focused on the work in front of you.

What changed

Details of this release

Receiving Analytics is now two tabs

The page opens on ERP Data, which is exactly the page you had before: the same filters, the same charts, the same reading of Infor Visual. Nothing on that tab has been retuned or moved.

The second tab, App Data, reads our own completed receiving records instead of Infor Visual. It carries its own date range, period and unit, so changing the App Data filters never disturbs the ERP Data tab, and changing the ERP Data filters never disturbs App Data.

Four App Data panels, one per page

App Data is split into four pages, chosen from a row of tabs with the filter bar above it:

  • Activity: loads, labels and quantity, switched between day, week and month.
  • On Time: receipts counted as early, on time or late against the purchase order due date, with an on-time percentage.
  • Suppliers: suppliers ranked by labels, quantity or loads, with the leading suppliers' share of the total and a remainder.
  • Coverage: our receipts beside what Infor Visual recorded for the same days and the same part numbers, plus how each side splits material by category.

Each page carries one plain sentence above the chart saying what its figures are read from, and reloading or clearing the filters leaves you on the page you were reading.

On-time results turn red or green against a target

A new administrator setting, Receiving Analytics on-time target, defaults to 95 per cent. With a target set, the on-time percentage appears green at or above it and red below it, with the target shown beside the number. With no target configured, the percentage is shown plainly with no colour so it cannot be mistaken for a pass or a fail.

Weekends are left out of App Data

Saturday and Sunday are not counted on App Data. No weekend day appears on a day axis, and weekend receipts contribute to no total, including the supplier ranking. The Infor Visual side of the coverage chart drops the same weekend dates, so the two lines stay aligned.

Coverage compares only the material we handle

Infor Visual records material that never flows through this app, so counting all of it made the comparison look like the app was missing work it was never asked to capture. Coverage now counts only the part numbers our own receipts carry for the selected dates.

Both sides also count purchase order lines on the day each line was last received, which is how Infor Visual dates a line. In a recent thirty-day window that gives 271 of our purchase order lines against 291 from Infor Visual, so the honest coverage figure is about 93 per cent rather than a misleading ratio of labels to lines.

Batch filter in Edit Mode

Edit Mode has a new Batch list beside the existing filters. Each entry is the set of skids that were entered together for a single part, and choosing one narrows the grid to that batch. The first entry clears the filter and shows every batch again.

The list also tells you how many rows each batch holds, so it is clear before you pick one what you are about to work on.

The app now starts and updates through MTM Loader

This release is published in the form the new MTM Loader expects, so the Receiving tile can copy the latest version onto a machine and start it without anyone reinstalling by hand.

The application carries everything it needs, so a machine no longer depends on anything preinstalled, and it does not need administrator rights.

Why it matters

What this means on the floor

You can see the work the ERP cannot

Infor Visual knows what arrived at the plant. Only this app knows who received it, when it was completed, and whether it beat the due date. App Data is the first place those answers are on screen.

You can tell whether the app is capturing the work

The Coverage page puts our receipts beside Infor Visual's for the same material. A gap there is real: it means material arrived that the app did not record.

Corrections stay focused

The Batch filter in Edit Mode shows the skids from one workflow step, instead of every load of that part that has ever been received.

What you need to do

Nothing is required to start using this release

No action is required after this update.

  • ERP Data behaves exactly as it did before, so anyone who only uses that tab has nothing to learn.
  • App Data is read only. It never changes a receiving record and never writes to Infor Visual.
  • The on-time target is already set to 95 per cent. Ask your MTM IT support team if your area needs a different figure.
  • The database changes that support App Data are applied separately by the MTM IT support team; there is nothing for you to run.

Need help?

Reporting a problem

If a figure on App Data does not match what you expect, the Coverage page shows a gap you cannot explain, an on-time percentage looks wrong, the Batch list in Edit Mode is empty, or the application will not start from the MTM Loader, contact your supervisor or the MTM IT support team and include the version number shown at the top of this page.
