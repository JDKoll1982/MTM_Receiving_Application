Version 1.4.0

This update adds quick label-launch support in Receiving and introduces new settings pages that let your team manage the LabelView program path and the label template files used by Receiving, Dunnage, and Volvo.

Version 1.4.0 Released April 29, 2026

Highlights

What's new in this release

Receiving label buttons

The Receiving workflow now includes quick buttons for the main Receiving Label and the Mini-Receiving Label.

Central LabelView setup

A new settings page lets IT or supervisors save the LabelView executable path once instead of relying on each user to browse for it.

Per-module label file paths

Receiving, Dunnage, and Volvo now each have dedicated settings pages for the label templates their teams use.

What changed

Details by area

Receiving can open label templates directly from the workflow

Two new buttons were added to the Receiving workflow footer: Receiving Label and Mini-Receiving Label. When those label paths are configured, the app opens the selected LabelView template directly instead of making users leave the workflow to find it manually.

New LabelView executable settings page

The Settings area now includes a dedicated LabelView page under the Core hub. That page stores the full path to LV.exe and keeps the expected default install path visible, which makes setup easier on shared workstations and after machine replacement.

Receiving, Dunnage, and Volvo each have label-file settings pages

New Label Files pages were added to the Receiving, Dunnage, and Volvo settings hubs. These pages save the exact .lbl template paths used by each area, so operators and supervisors can keep setup organized by workflow instead of relying on shared notes or manual file browsing.

Missing setup now sends users to the right settings page

If LabelView is not configured yet, or if a required label file path is missing, the new Receiving buttons route the user to the matching settings page instead of failing silently. This makes first-time setup and support troubleshooting much clearer.

Why it matters

What this means for daily work

Fewer extra steps

Operators can get to the right label template faster because the workflow now opens the file directly when setup is already complete.

Cleaner setup

Supervisors and IT now have clear pages for the LabelView program path and each workflow's template files instead of relying on workstation memory.

Easier support handoff

When something is missing, the app points users to the exact settings page that needs attention, which reduces back-and-forth during support calls.

What you need to do

No immediate action is required

No action is required to keep using your current workflows.

  • If your team wants to use the new quick label buttons, have a supervisor or IT confirm the LabelView path in Settings.
  • Have the appropriate Receiving, Dunnage, or Volvo label template paths entered once for the workstation or environment.

Need help?

Questions or setup issues?

If a label button does not open the expected template after the update, note the version number shown at the top of this page (1.4.0) and contact your supervisor or the MTM IT support team. They should verify the LabelView executable path first, then the module-specific label file path.
