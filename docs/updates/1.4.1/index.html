Highlights

What's improved in this release

Cleaner LabelView reuse

Labels now open the same way a desktop shortcut opens them, which gives LabelView a better chance to reuse the current session.

Open-folder shortcuts

Each new label-path editor now includes an Open Folder button so support staff can jump to the saved location quickly.

Tidier footer actions

The Receiving label buttons now use compact icons beside Help instead of crowding the Back and Next controls.

What changed

Details by area

Labels now open the same way a desktop shortcut opens them

The app now opens each .lbl file through Windows shell behavior after confirming that LabelView is installed. This matches the way a desktop shortcut opens a label file, which makes it more likely that an existing LabelView session will be reused instead of opening extra windows.

Receiving label buttons no longer crowd the main navigation

The Receiving label actions were changed from full text buttons to compact icon buttons and moved beside the Help button. Back and Next keep their own space, which makes the footer easier to use during the workflow.

Label path pages now include Open Folder buttons

The LabelView executable page and the Receiving, Dunnage, and Volvo label-file pages now include an Open Folder button next to each saved path. If the saved folder is available, File Explorer opens there. If not, the app falls back to the current user's Documents folder so support staff still land in a safe location.

Path troubleshooting is easier during support calls

Support staff can now inspect saved label folders directly from the settings pages instead of copying and pasting long paths into File Explorer by hand.

Why it matters

What this means on the floor

Less window clutter

Opening labels more like a normal Windows shortcut reduces the chance of piling up extra LabelView windows for the same task.

Faster path checks

When a label path needs review, supervisors and IT can jump straight to the folder instead of browsing from scratch.

Clearer workflow footer

The footer now keeps help and label actions together while leaving the main navigation controls easier to see and click.

What you need to do

No action is required

No action is required after this update.

Your existing LabelView and label-file settings continue to work. This update improves how those settings behave during everyday use and support troubleshooting.

Need help?

Questions or label issues?

If a label still does not open as expected after this update, note the version number shown at the top of this page (1.4.1) and contact your supervisor or the MTM IT support team. They should first verify the saved executable and label folders using the new Open Folder buttons in Settings.
