Version 2.5.0

This update adds contextual guidance text to the Receiving and Dunnage workflow headers, tightens reconciliation accuracy with a strict date-scoped validation check, and cleans up redundant on-screen headers across settings and workflow views.

Highlights

What stands out in this release

Step-by-step guidance in the header

Receiving and Dunnage workflow pages now show a short description of the current step directly in the application header, so you always know what to do next without opening a help panel.

Reconciliation is more precise

The app now verifies that the total quantity assigned to each receiving location exactly matches what Infor Visual recorded for that location on the receipt date. Rows that don't match are flagged for manual review instead of being saved with a questionable location.

Cleaner settings and workflow screens

Redundant title and description blocks have been removed from settings and workflow views. The same context is now shown in the page header, which keeps each screen less cluttered.

What changed

Details by area

Receiving workflow now shows a short guide line for each step

While you move through Receiving — from PO entry through part selection, weight and quantity entry, heat and lot, package type, and final review — the application header shows a plain-language sentence explaining what that step is asking you to do. The text updates automatically as you advance through the workflow.

Dunnage workflow header now shows the selected part type with image or icon

During the Dunnage Part Selection step, the page header updates to show the name of the selected dunnage type alongside its image or icon. The header also shows a brief guide line during Quantity Entry and Details Entry steps, consistent with how the Receiving workflow behaves.

Dunnage display format toggle moved to the action button row

The switch that toggles between part drop-down and image card view has moved from a standalone card at the top of the Part Selection form to the right side of the action button bar at the bottom. This frees up vertical space and groups the control closer to where parts are displayed. The toggle now also shows a tooltip that describes what will happen when you click it.

Reconciliation rejects ambiguous allocations when quantity totals don't match exactly

Previously, the app could assign a receiving row to a destination location even when the combined quantity of rows assigned to that location didn't match the actual quantity Infor Visual recorded being transferred there on the receipt date. Those rows are now marked as Ambiguous and returned to Needs Attention so an operator can review them directly.

Rows where no transfer was found no longer appear in the reconciliation review list

When reconciliation finds no transfer history for a receiving row, it now treats that as "no evidence of a location change" — the saved location is assumed to still be current and the row is not shown under Needs Attention. Only rows that have active evidence of a conflict, an error, or an ambiguous match are surfaced for review.

Current-label and history rows are now reconciled together in one pass

Previously, rows from the Current Labels source and rows from History were reconciled in two separate passes, which could cause the app to miss relationships between rows from different sources that share the same part and receipt date. They are now grouped and reconciled together so cross-source comparisons work correctly.

Settings and workflow screens no longer repeat the page title inside the content area

Several settings pages — including Label Files, Keyboard Shortcuts, Workflow Defaults, Shared Paths, UI Theme, and LabelView Executable — previously showed a title and description block at the top of the content area in addition to the title shown in the settings window sidebar. Those embedded headers have been removed. The page title and description now come from the settings navigation sidebar only. The settings window navigation for Keyboard Shortcuts pages has also been updated with correct display names.

Why it matters

What this means in practice

Less time orienting during the workflow

The guide text in the header gives operators a quick reminder of what each step expects without requiring them to open help or look for a label inside the page content.

Fewer incorrect location saves in reconciliation

The new date-scoped quantity check catches cases where the app would have previously saved a location based on a partial match. Those rows now stay in Needs Attention so the correct location can be confirmed manually.

A less cluttered screen on every settings page

Removing duplicate header blocks from settings views leaves more room for the actual controls and reduces visual noise during configuration tasks.

What you need to do

No action required

No action is required after this update. All workflow guide text, reconciliation improvements, and screen layout changes take effect automatically after the new version is installed.

  • Look for the short guide line in the page header as you step through Receiving or Dunnage — it updates automatically at each step.
  • If a reconciliation row appears under Needs Attention with an "Ambiguous" status, review it manually and apply the correct location using the review grid.
  • Rows labeled "NotFound" in reconciliation are now treated as having a current, valid saved location and will not appear in the review list.

Need help?

Questions about the new workflow guidance or reconciliation behavior?

If a reconciliation row is stuck in Needs Attention after this update, or if any workflow step shows unexpected behavior, contact your supervisor or the MTM IT support team and reference version 2.5.0.
