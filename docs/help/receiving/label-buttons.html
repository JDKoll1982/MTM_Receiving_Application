Using the Receiving Label Buttons

The Receiving workflow includes two quick label buttons that open the configured LabelView templates without leaving the workflow. This page explains what each button does, what the app checks first, and what happens if a required path is missing.

Overview

The label buttons are shortcut actions for the templates most Receiving users need during daily work. They are meant to save time by opening the configured label directly from the workflow instead of making you browse to the label file by hand.

🏷️
The buttons open LabelView templates only after validation. Before anything opens, the app checks that LabelView is configured and that the selected label file path is valid.

Where the buttons are

The label buttons sit in the bottom-right utility area of the Receiving workflow beside the Help button. They use compact icons so they do not crowd the main Back and Next workflow buttons.

✅
Keep using Back and Next for the workflow itself. The label icons are utility shortcuts and do not change your current wizard step.

What each button opens

  • Receiving Label opens the main Receiving label template.
  • Mini-Receiving Label opens the smaller Receiving label template.

Each button uses the path saved in the Receiving settings page. If your workstation is configured correctly, the app opens the selected .lbl file the same way a Windows shortcut would open it.

Before you use them

1

LabelView must be installed and configured

The app first checks the saved path to LV.exe. If that path is missing or no longer valid, the label will not open.

2

The label file path must point to a real .lbl file

The app then checks the saved path for the specific label button you clicked. If the file is missing, renamed, or moved, the app will send you to the settings page instead of guessing.

3

The label opens through Windows

When both checks pass, the app opens the label through normal Windows shell behavior. This gives LabelView the chance to reuse an already open session instead of forcing a separate new one.

If setup is missing

The app does not try to open a label when setup is incomplete. Instead, it sends you to the correct settings page.

LabelView is not configured
The app opens the LabelView settings page under Core settings so the saved executable path can be reviewed.
The label file path is missing or invalid
The app opens the Receiving Label Files settings page so the saved template path can be corrected.
⚠️
The app will not guess a replacement label file. If the path is wrong, it always sends you to settings so you can confirm the correct file.

Checking saved paths in Settings

The LabelView page and each label-path page include an Open Folder button beside the saved path. That button is meant for support and setup checks.

  • If the saved file exists, File Explorer opens with that file selected.
  • If the file does not exist but the folder still does, Explorer opens the folder.
  • If no usable folder can be found yet, Explorer opens your Documents folder.
📁
This is useful when a label was moved, renamed, or copied to a different network folder and you need to confirm what the app is pointing to.

Common Questions

Do the label buttons save or submit my receiving work?
No. They only open the configured label template. They do not change your current wizard step and they do not save data by themselves.
Why did Settings open instead of LabelView?
One of the required paths could not be validated. The app sends you straight to the page that needs to be fixed.
Will clicking the button always open a new LabelView window?
The app opens the label the same way Windows opens a shortcut to the file. LabelView itself decides whether it reuses the current session or opens another window.
Who should update the saved label paths?
Usually a supervisor or IT support person should update those paths, especially when the labels live in shared network folders.
