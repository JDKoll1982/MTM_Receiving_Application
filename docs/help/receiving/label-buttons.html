Using the Label Buttons

The main window has a row of label shortcut buttons at the bottom of the left navigation pane. Each one opens a configured LabelView template in a single click. This page explains which buttons you get, how to change them, what the app checks first, and what happens if a required path is missing.

Overview

The label buttons are shortcut actions for the label templates you use most often. They save time by opening the configured label directly instead of making you browse to the label file by hand.

🏷️
The buttons open LabelView templates only after validation. Before anything opens, the app checks that LabelView is configured and that the selected label file path is valid.

Where the buttons are

The buttons sit in a row at the bottom of the left navigation pane, underneath the module links and just above the bottom edge of the window. They appear on every screen, so you do not need to navigate anywhere first.

Each button is a small square icon button. Hover over one and a tooltip tells you exactly which label it opens — for example Open Receiving.

If you have more buttons than fit on one row, a pair of small up and down arrow buttons appears at the right-hand end of the row. Use them to page through the rest of your buttons.

✅
Keep using Back and Next for the workflow itself. The label buttons are shortcuts and do not change your current wizard step.

What each button opens

A new user starts with four label buttons:

  • Receiving (green) — the main Receiving label template.
  • Mini Receiving (red) — the smaller Receiving label template.
  • Dunnage (blue) — the Dunnage label template.
  • Volvo (black) — the Volvo label template.

Each button uses a path saved in your own settings, so different operators on the same computer can point at different files. When the path is valid, the app opens the selected .lbl file the same way a Windows shortcut would open it.

ℹ️
The set of buttons is yours to change. You can add, copy, rename, or remove buttons, and you can turn individual buttons off without deleting them — up to ten enabled buttons. See the next section.

Managing your buttons

Right-click any label button to open its menu. The menu has three options:

Menu option What it does
Edit Opens the LabelView settings page so you can review or correct the saved executable path.
Duplicate Creates a copy of the button directly after it, named the same with Copy appended. The copy starts with the same label path, so edit it afterwards.
Delete Removes the button from your row. The other buttons close the gap and stay in order.

Your button setup is saved to your own account, not to the computer, so it follows you to any workstation you log into.

⚠️
Ten enabled buttons is the limit. If you try to duplicate past ten, the app shows a message instead of adding one. Remove a button you no longer need, or disable it, if you have run out of room.

Before you use them

1

LabelView must be installed and configured

The app first checks the saved path to LV.exe. If that path is missing or no longer valid, the label will not open.

2

The label file path must point to a real .lbl file

The app then checks the saved path for the specific label button you clicked. If the file is missing, renamed, or moved, the app will send you to the settings page instead of guessing.

3

The label opens through Windows

When both checks pass, the app opens the label through normal Windows shell behavior. This gives LabelView the chance to reuse an already open session instead of forcing a separate new one.

If setup is missing

The app does not try to open a label when setup is incomplete. Instead, it sends you to the correct settings page.

LabelView is not configured
The app opens the LabelView settings page under Core settings so the saved executable path can be reviewed.
The label file path is missing or invalid
The app opens the label-file settings page for that button's module — for example Receiving Label Files for the Receiving buttons, or the Dunnage or Volvo label-file page for those buttons — so the saved template path can be corrected.
⚠️
The app will not guess a replacement label file. If the path is wrong, it always sends you to settings so you can confirm the correct file.

Checking saved paths in Settings

The LabelView page and each label-path page include an Open Folder button beside the saved path. That button is meant for support and setup checks.

  • If the saved file exists, File Explorer opens with that file selected.
  • If the file does not exist but the folder still does, Explorer opens the folder.
  • If no usable folder can be found yet, Explorer opens your Documents folder.
📁
This is useful when a label was moved, renamed, or copied to a different network folder and you need to confirm what the app is pointing to.

Common Questions

Do the label buttons save or submit my receiving work?
No. They only open the configured label template. They do not change your current wizard step and they do not save data by themselves.
Why did Settings open instead of LabelView?
One of the required paths could not be validated. The app sends you straight to the page that needs to be fixed.
Will clicking the button always open a new LabelView window?
The app opens the label the same way Windows opens a shortcut to the file. LabelView itself decides whether it reuses the current session or opens another window.
Who should update the saved label paths?
Usually a supervisor or IT support person should update those paths, especially when the labels live in shared network folders.
