Starting the App

When you launch the MTM Receiving Application a startup screen appears while the app loads in the background. This page explains what that screen shows, what the progress messages mean, and what happens when the app finishes starting — especially if you are logging in for the first time on this computer.

What You See

While the app is loading you will see a startup window with the MTM logo, the application name and version, a short status message, how far along the startup steps are as a percentage, and a blue progress bar.

The startup screen — you do not need to click anything

ℹ️
You do not need to do anything during startup. The app handles everything automatically. Simply wait for the progress bar to complete and the main window to open.

Status Messages

The text underneath the progress bar changes as the app moves through each startup step. Here is what each message means, in the order they appear:

Message you see What the app is doing
Starting application… Kicking off startup — the very first step.
Loading main window… Building the main application window behind the startup screen.
Initializing services… Setting up the app's internal components and background services.
Preparing Dunnage image assets… Checking the Dunnage image folder on this computer.
Syncing Dunnage images from network… Copying Dunnage images that are not on this computer yet. The progress bar pauses on this step because the amount of work is not known in advance.
Dunnage image assets ready. Dunnage images are up to date.
Checking user account… Looking up your Windows username in the user database.
User account not found. Waiting for account creation… No profile exists for your Windows username, so the New User Entry window has opened over the startup screen. The bar pauses until you finish or cancel.
Employee account created… Your new account was saved and the app is reloading it.
Account created for your name Your new account is ready and being loaded.
Detecting workstation configuration… Working out whether this computer is a personal workstation or a shared terminal.
Personal workstation - Windows authentication This is your own computer, so you are signed in automatically with your Windows login. No PIN is needed.
Shared terminal detected. Waiting for PIN login… This is a shared terminal, so the Shared Terminal Login window is asking for your username and 4-digit PIN. The bar pauses until you log in.
Welcome, your name Your identity is confirmed.
Creating user session… Building your session profile from your saved preferences.
Initializing core settings… Loading the application settings that every module shares.
Verifying application version… Confirming the installed version is correct before the module windows open.
Ready! Startup complete — the main window is about to open.
ℹ️
The progress bar pauses on some steps. Messages such as Syncing Dunnage images from network…, User account not found… and Shared terminal detected… stay on screen until the app has finished that step or until you complete a window it opened. You will not see every message on every computer.
⚠️
The startup screen stays open for longer than usual? The two slowest steps are Syncing Dunnage images from network…, which copies image files the first time you use a computer, and Detecting workstation configuration…, which reaches the database. If the app sits on Preparing Dunnage image assets… or Detecting workstation configuration… for more than 20–30 seconds, the app may not be able to reach the network. Check that you are on the plant network (or VPN) and let your supervisor or IT know.

Personal Computer or Shared Terminal?

Partway through startup the app works out what kind of computer it is running on, because that decides how you sign in. You do not choose this — it is configured per computer by IT.

Personal workstation

  • The computer is yours, so you are signed in automatically using your Windows login.
  • No login window appears and no PIN is needed.
  • The status message reads Personal workstation - Windows authentication.

Shared terminal

  • The computer is used by many people, so the app cannot assume who you are.
  • A Shared Terminal Login window opens asking for your Username and your 4-digit PIN.
  • Select Login to continue, or Cancel to close the application.
  • If the details are wrong you will see a Login Failed message and can try again.
  • After too many failed attempts the app locks the login and closes for security — ask your supervisor if this happens.
ℹ️
Choosing your PIN. The PIN you set during New User Entry is what you type at a shared terminal. It is entered on its own after your username, so it does not need to be shared with anyone else.

First Time on This Computer?

When the app reaches Checking user account…, it checks whether your Windows username already has a profile in the receiving database.

  • Returning user — your profile is found and startup carries on to the login step for this computer.
  • First time on this computer — no profile is found for your Windows username, so the app opens the New User Entry window on top of the startup screen. The progress bar pauses while it is open.

The New User Entry window collects everything the app needs about you, grouped into six sections:

Section What you provide
Name Your first and last name.
Employee Details Your employee number. Your Windows username is filled in for you.
Department Assignment Your department, or a custom department name if yours is not in the list.
Work Schedule Your shift.
Account Security A 4-digit PIN, entered twice. This is the PIN you use to log in at a shared terminal.
ERP System Access Your Infor Visual (ERP) username and password.
📋
New User Entry opens automatically — you do not need to find it yourself. Have your employee number, department, shift, and Infor Visual (ERP) username and password ready.

See the New User Setup guide for a complete walkthrough →
⚠️
If you close the New User Entry window without finishing, the application closes. Nothing is saved and you are back where you started. Start the app again and complete the form in one go.

Common Questions

The startup screen appeared and then disappeared. Is something wrong?
No — that is normal. The startup screen closes automatically once the app is fully loaded and the main window is ready. If the main window did not appear after the splash screen closed, check the Windows taskbar; the app may have opened behind another window.
After startup, a "New User Entry" form opened. What do I do?
The app could not find a profile for your Windows username so it launched the setup form automatically. Fill it in to create your account. See New User Setup for a step-by-step guide.
A "Shared Terminal Login" window is asking for a PIN. What is that?
This computer is set up as a shared terminal, so the app cannot tell who is sitting at it. Enter your username and the 4-digit PIN you created during New User Entry, then select Login. On a personal workstation this window never appears.
The app closed itself during login. Why?

Two things close the application on purpose:

  • You cancelled the login — selecting Cancel on the Shared Terminal Login window, or closing the New User Entry window without finishing, ends startup.
  • Too many failed PIN attempts — the app locks the login and closes for security. Ask your supervisor to help you get back in.
The app shows an error during startup instead of opening normally.

Common causes:

  • Not on the plant network — the app needs to reach the MySQL and Infor Visual servers, and to sync Dunnage images. Make sure you are connected to the plant LAN or the company VPN.
  • Database server is down — contact IT to check server status.
  • The installed version is out of date — if startup stops on Verifying application version…, the app is telling you it needs updating. Contact IT for the current installer.
  • App needs to be re-installed — if the error mentions a missing file, contact IT for a fresh installation.
How long should startup normally take?
On a healthy network the startup screen should complete in under 10 seconds. If it consistently takes longer, report it to IT so they can check database connection performance.
