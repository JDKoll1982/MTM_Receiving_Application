🗄️ Table

volvo_label_data

Header records for Volvo dunnage shipments. One row represents a single shipment — the date, its day sequence number, the PO, and the receiver number once it has been received in Infor Visual.

Overview

A shipment starts life as pending_po while Purchasing is still creating the purchase order, then moves to completed once the PO and the Infor Visual receiver number are known. The line items for each shipment live in volvo_line_data.

Shipment numbers restart each day, so a shipment is only unique in combination with its date — enforced by the unique_shipment_per_day key.

Usage Notes

  • Never look up a shipment by shipment_number alone — it repeats daily. Always include shipment_date.
  • status only has two values. Anything that looks like a third state is derived from the line-level po_status in volvo_line_data.
  • is_archived is a soft delete — active-queue queries must add WHERE is_archived = 0.
  • Deleting a shipment cascades to its lines: volvo_line_data uses ON DELETE CASCADE.
  • Clearing label data copies completed shipments into volvo_label_history and flags this row as archived.
