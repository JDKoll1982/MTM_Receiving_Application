🗄️ Table

dunnage_parts

Master data for the physical dunnage items the plant tracks. Each row links a scannable part identifier to a dunnage type, a printed quantity label, and the site-specific custom columns the operator fills in.

Overview

This table is the dunnage equivalent of a part master. When dunnage is received, the operator scans or picks a part_id from here, and the quantity_type supplies the header shown on the printed label (for example Quantity or Skids).

The ten udc slots are generic user-defined columns. Their display names come from dunnage_custom_fields, which lets each plant rename the extra fields without a schema change.

Usage Notes

  • part_id is the value an operator scans, so it must match the physical label exactly.
  • A part cannot be deleted while dunnage_history rows reference it — the foreign key is RESTRICT.
  • quantity_type travels with the part; changing it here affects future labels, not ones already printed.
  • Do not treat the udc columns as having fixed meanings — read dunnage_custom_fields for the current labels before writing queries for reports.
