🗄️ Table

receiving_label_data

The active receiving queue. Rows accumulate here during an in-progress receiving session. When the operator completes the session, sp_Receiving_LabelData_ClearToHistory moves all rows for that session into receiving_history and deletes them from this table.

Overview

This table acts as the working buffer for the receiving workflow. A session is identified by the load_id GUID. Multiple labels from the same session share the same load_id.

The schema mirrors receiving_history closely because rows are promoted into history verbatim. The key difference is that load_id here may be NULL until the workflow assigns it.

⚠️
Transient data. Rows in this table represent in-flight sessions. If a session was never completed (operator abandoned the workflow), orphaned rows may remain. The application does not automatically purge abandoned sessions.

Usage Notes

  • Do not read this table for historical reporting — use receiving_history instead.
  • Rows here with the same load_id all belong to a single receiving session.
  • If load_id is NULL, the session was not yet finalised when the row was written.
  • Rows are removed from this table after a successful call to sp_Receiving_LabelData_ClearToHistory.
