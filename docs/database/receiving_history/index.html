🗄️ Table

receiving_history

The primary transaction ledger for all completed receiving events. Rows are written here (via stored procedure) when the receiving workflow completes. This table is append-only — rows are never updated or deleted through the application.

Overview

Every time an operator completes a receiving session the app calls sp_Receiving_LabelData_ClearToHistory, which moves records from the active receiving_label_data queue into this table. This ensures that receiving_history contains only fully committed transactions.

Historical import rows (pre-app data migrated from spreadsheets) appear here with load_guid = NULL to distinguish them from application-generated rows.

Usage Notes

  • Always filter by transaction_date when querying for reports — this is the indexed date column.
  • Use load_guid IS NULL to exclude imported rows from application-only queries.
  • is_non_po_item = 1 rows will have po_number = NULL.
  • Quality hold fields (is_quality_hold_required, is_quality_hold_acknowledged) are informational snapshots captured at receive time.
  • Snapshot columns (vendor_name, part_description, po_status, etc.) preserve the state of Infor Visual data at the moment of receiving. Do not join back to Infor Visual expecting to get the same values — they may have changed since.
