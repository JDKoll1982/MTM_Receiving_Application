🗄️ Table

receiving_package_types

Stores the user's remembered package type preference per part number. When a part is received, the app pre-selects the last-used package type from this table to reduce re-entry.

Overview

This is a small lookup/preference table. Each row maps one Infor Visual PartID to a package type choice (e.g., Skid, Box, Pallet, Custom). The unique constraint on PartID enforces a one-preference-per-part rule — updating the preference is an INSERT … ON DUPLICATE KEY UPDATE.

When PackageTypeName is Custom, the CustomTypeName column holds the user-defined label text.

Columns

ColumnTypeNullableDescription
PreferenceIDINT PK AUTONoSurrogate primary key
PartIDVARCHAR(50) UNIQUENoInfor Visual part identifier; unique constraint
PackageTypeNameVARCHAR(50)NoSelected package type (Box, Pallet, Custom, etc.)
CustomTypeNameVARCHAR(100)YesUser-defined type name when PackageTypeName = "Custom"
LastModifiedDATETIMENoTimestamp of last preference update

Usage Notes

  • Row count is bounded by the number of unique parts ever received — typically a few hundred rows.
  • Managed via Settings → Receiving as well as implicitly when a receiving session completes.
  • Never joins to receiving_history at query time; the resolved value is snapshotted into package_type_name on the history row at receive time.
