🗄️ Table

dunnage_history

The transaction ledger for received dunnage. Rows arrive here when the Clear Label Data action moves the active dunnage queue out of dunnage_label_data, so this table contains only completed work.

Overview

Each row is one dunnage receipt: a part, a quantity, the date it was received, and who recorded it. Because the row is a copy of an active queue row, it also carries snapshots of the dunnage type and the user-defined column captions exactly as they were at the time.

Every archive operation stamps the same archive_batch_id onto all the rows it moved, which makes a single Clear Label Data run easy to isolate or reverse.

Usage Notes

  • Filter by received_date for date-range reporting — it is the indexed business date.
  • archived_at is the technical move time; received_date is when the dunnage actually arrived. They are usually different.
  • Use archive_batch_id to find every row produced by one Clear Label Data run.
  • The type_* and dunnage_type_* pairs hold the same meaning; older rows populate the first set, newer rows may populate either. Check both when reading history.
  • Snapshot columns preserve what the record looked like at archive time — do not join back to dunnage_parts or dunnage_types expecting identical values.
  • po_number IS NULL indicates a non-PO dunnage receipt.
