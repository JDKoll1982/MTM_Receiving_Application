🗄️ Table

volvo_line_data

The part-level detail of each Volvo shipment. Every row is one part on one shipment — how many skids were counted, how many pieces that works out to, and whether the count disagreed with Volvo's packlist.

Overview

Lines belong to a shipment header through shipment_id. Each line carries a quantity-per-skid snapshot taken from master data, the skid count the operator entered, and a stored piece count so historical figures do not shift when master data changes later.

A line is Pending until it has been received in Infor Visual, at which point po_status becomes Received.

Usage Notes

  • quantity_per_skid and calculated_piece_count are deliberate snapshots. Do not recompute them from master data when reporting history — the numbers would change.
  • po_status is free text, not an enum, so filters should be written case-insensitively or matched exactly as written by the app (Pending, Received).
  • Discrepancy reporting should filter on has_discrepancy = 1 rather than comparing counts at query time.
  • Deleting a shipment header cascades and removes its lines.
  • A part cannot be removed from master data while shipment lines reference it — the foreign key is RESTRICT.
