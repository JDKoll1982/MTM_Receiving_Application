MTM Agent Toolkit

Every plugin, skill, agent, canvas, and MCP server available to this workspace, organised by the job you are trying to do.

Why this book exists

This workspace carries thirteen plugins worth of tooling, seventy-one skills, fifty plugin and repo agents, four canvas surfaces, and a hundred-plus repo prompts. Nothing described them in one place, so the only way to discover a tool was to already know it existed.

This book fixes that. It is organised by what you are trying to do, not by which plugin happens to own the tool, because plugin boundaries are invisible to someone who does not already know the plugins.

One rule about counts. A skill bundled by two plugins is documented once, naming both sources, and counted once. That is why the book claims 71 unique skills while the disk holds 72 skill directories.

How to read this book

  1. Arriving with a task. Open the chapter whose title matches the job, scan the entry purposes, and read the one that fits. Every entry states what it does, when to reach for it, what it needs, and what it will not do.
  2. Arriving with a name. Use the search box in the sidebar, or open the index by source and filter by plugin name. Nothing in this workspace is missing from that index.
  3. Choosing between two tools. Open the which tool when page. Overlapping tools are the most common failure mode in a set this size, so each overlap has a stated default, a reason, and the condition where the other option wins.
  4. Needing the exact invocation. Every skill and agent entry carries a copy-ready prompt. Copy it, adjust the module name, run it.
  5. Wanting paper. Open the print edition. One Print action produces a cover page, a contents page, and every chapter starting on a fresh page at US Letter.

    This book goes stale. Plugins update and skills appear. Run python check-drift.py from the book folder after any plugin change. It is read-only, reports missing, stale, version-changed, and newer-available tools, and exits non-zero when the book no longer matches the machine.

    One maintenance note. The twelve chapter files are the source of truth and are edited directly. index-by-source.html, print.html, and assets/search-index.json are derived from them. After editing a chapter run python build-pages.py to rebuild those three, and python build-pages.py --check to confirm they are current. The drift check catches broken anchors, missing assets, and missing search records, but only the builder keeps the print edition in step with the chapters.
