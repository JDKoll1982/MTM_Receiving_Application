Chapter 07

Code quality and review

Keeping the test suite honest. Everything here operates on MTM_Receiving_Application.Tests/, which is xUnit with FluentAssertions, method names of the form MethodName_ShouldResult_WhenCondition, integration tests built on IAsyncLifetime, and test data prefixed TEST-.

Run the suite with dotnet test MTM_Receiving_Application.Tests/MTM_Receiving_Application.Tests.csproj. The audit skills below report; the authoring skills and agents fix what they find.

WinUI XAML and binding review is documented in the WinUI chapter, not here, so it is not double-counted: see winui-code-review.

assertion-quality

dotnet-test@1.0.0

Audits assertion depth, variety, and false confidence in existing tests, flagging always-true, self-referential, and presence-only checks.

  • Checking whether a ViewModel test asserts behavior, or only that a method returned something non-null.
  • Finding FluentAssertions chains that restate the implementation instead of verifying the observable outcome.
  • Reviewing DAO tests for truthiness-only assertions that would still pass if the wrong row came back.
Prerequisites
Existing test files to analyze. It reports findings; it does not rewrite anything.
Boundaries
Identifies weak assertions only. Writing the replacement assertions is owned by code-testing.
Use the assertion-quality skill on MTM_Receiving_Application.Tests/Unit for the
Module_Receiving viewmodels. Flag every test whose FluentAssertions only checks
truthiness or restates the implementation, and list what each assertion should verify
instead.

grade-tests

dotnet-test@1.0.0

Grades curated individual tests A through F for readiness and quality against this repo's naming, fixture, and assertion conventions.

  • Scoring one named test method to decide whether it survives a refactor.
  • Grading the integration tests in MTM_Receiving_Application.Tests/Integration/ for correct IAsyncLifetime setup and cleanup.
  • Producing a per-test quality band for a bounded diff before a code review.
Prerequisites
A named test method, class, or bounded file span to grade; it does not choose scope for you.
Boundaries
Grades quality only. It never edits the tests it scores.
Use the grade-tests skill on the Dao_ReceivingLine integration tests in
MTM_Receiving_Application.Tests/Integration. Grade each test A through F on naming
(MethodName_ShouldResult_WhenCondition), IAsyncLifetime cleanup, and assertion
quality, and report which ones need a rewrite.

test-anti-patterns

dotnet-test@1.0.0

Severity-ranked audit of tests that verify nothing, tautological assertions, swallowed or broad exceptions, and flaky or order-dependent behavior.

  • Scanning the receiving module's tests for exceptions caught and ignored instead of asserted.
  • Detecting FluentAssertions checks that compare a value against itself.
  • Surfacing xUnit tests that pass in sequence but fail when run alone.
Prerequisites
One or more test files to scan. The report is read-only.
Boundaries
Produces a diagnostic report; direct fixes belong to code-testing or test-engineer.
Use the test-anti-patterns skill on MTM_Receiving_Application.Tests. Report
severity-ranked anti-patterns with file and line, focusing on swallowed exceptions,
tautological assertions, and flaky order dependence across the xUnit tests.

test-smell-detection

dotnet-test@1.0.0

Audits tests using the formal testsmells.org 19-smell academic taxonomy, with named categories and severity ranking.

  • Mapping an existing suite onto the 19 formal smells for a citable review.
  • Distinguishing Eager Test and Assertion Roulette smells inside long integration tests.
  • Producing an academic-style taxonomy report for one module's test folder.
Prerequisites
Test files to analyze. Returns named smell categories, never fixes.
Boundaries
Uses the academic 19-smell catalog only; for a quick pragmatic review use test-anti-patterns.
Use the test-smell-detection skill on MTM_Receiving_Application.Tests/Integration.
Name each finding by its testsmells.org category (for example Assertion Roulette or
Eager Test) and rank by severity, with file and line for each.

test-tagging

dotnet-test@1.0.0

Classifies existing tests by standard traits and reports the distribution of happy-path versus error-path coverage.

  • Tagging the receiving tests with category attributes so CI can filter a subset.
  • Auditing the test mix to confirm error paths are actually covered, not only happy paths.
  • Reporting which test categories are entirely missing from a module.
Prerequisites
Existing tests. Applies canonical category attributes when tagging is requested, otherwise reports only.
Boundaries
Classifies and tags; it does not write new cases or repair failing tests.
Use the test-tagging skill on MTM_Receiving_Application.Tests for Module_Dunnage.
Tag each test by trait and report the happy-path versus error-path distribution, then
tell me which categories have no coverage.

code-testing

dotnet-test@1.0.0

Writes, repairs, or strengthens tests for existing code in xUnit with FluentAssertions, following this repo's naming, fixture, and test-data rules.

  • Adding focused regression tests for a DAO method that currently has none.
  • Repairing a failing integration test so its IAsyncLifetime cleanup and TEST- prefix are correct.
  • Strengthening a FluentValidation validator test after a new rule is added.
Prerequisites
The production code to test, inside this repo's xUnit project.
Boundaries
Tests against existing seams only; it does not create production seams or migrate test frameworks.
Use the code-testing skill to add integration tests for Dao_ReceivingLine in
MTM_Receiving_Application.Tests/Integration. Use IAsyncLifetime for setup and cleanup,
prefix all test data with TEST-, name methods MethodName_ShouldResult_WhenCondition,
and assert with FluentAssertions.

test-quality-auditor

dotnet-test@1.0.0

The internal audit agent behind the assertion-quality, test-anti-patterns, and test-smell-detection skills, running combined multi-dimensional health checks.

  • Running one combined quality audit across a module's tests instead of three separate skill passes.
  • Producing a severity-ranked health report that spans assertion depth, anti-patterns, and named smells.
  • Auditing the whole test project before a release to list what must be fixed first.
Prerequisites
A scope of test files to audit. It reports findings and leaves code untouched.
Boundaries
Audits only; it does not apply fixes. Route fixes to code-testing or test-engineer.
Use the test-quality-auditor agent to run a combined audit of
MTM_Receiving_Application.Tests. Merge assertion-quality, anti-pattern, and
testsmells.org findings into one severity-ranked report with file and line, and list
the top ten fixes.

Choosing between them. Start with the audits (test-quality-auditor, test-anti-patterns, test-smell-detection, assertion-quality) to find what is weak, use grade-tests to prioritize, test-tagging to see the coverage shape, then hand the fix work to code-testing for one-off repairs or test-engineer for a full pass.
