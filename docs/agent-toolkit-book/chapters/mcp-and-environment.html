Chapter 11

MCP servers and environment

The servers, hooks, and language services that give the agent its eyes and hands: the MCP servers wired into the project and the user profile, the Speckit hook that journals every prompt, and the two C# language servers that divide symbol work from diagnostics.

Configuration lives in three places: .vscode/mcp.json for project scope, ~/.copilot/mcp-config.json for user scope, and .github/hooks/speckit.json for event hooks.

serena

.vscode/mcp.json (project scope)

Provides symbol-level navigation and editing backed by a Roslyn language server, returning one definition instead of a whole file.

  • Finding every caller of a DAO method with find_referencing_symbols before changing its signature.
  • Reading one method out of a 400-line class with find_symbol instead of loading the entire file.
  • Renaming a ViewModel property safely across C# and XAML with rename_symbol.
How it is configured
uvx --from git+https://github.com/oraios/serena serena start-mcp-server --context ide --project ${workspaceFolder}. The ide context keeps only symbol and memory tools, leaving file and shell work to the editor.
Boundaries
Exposes symbol editing, not a full diagnostics stream. Project settings live in .serena/project.yml; memories live in .serena/memories/. It will not edit non-code files such as JSON or YAML.
Use Serena to find every caller of Dao_ReceivingLine/GetLinesByLoadAsync, then
rename the method to GetLinesByReceiptAsync with rename_symbol and verify no
ViewModel now touches the old name.

playwright

~/.copilot/mcp-config.json (user scope)

Drives a web browser through Playwright for web-page inspection, interaction, and testing.

  • Exploring a web target that a reporting export or an internal dashboard opens in a browser rather than a desktop window.
  • Generating a Playwright test for a documented web flow so the scenario is captured as code.
  • Capturing a screenshot or the accessibility snapshot of a page during a web investigation.
How it is configured
npx @playwright/mcp@latest, registered in the user profile with all tools enabled.
Boundaries
Web targets only. This repository is a WinUI 3 desktop application, so Playwright cannot drive it; the WinUI UI-automation skills are the desktop equivalent.
Use Playwright to open the export preview page, capture the accessibility
snapshot, and confirm the grid columns match the report spec before writing any
UI-automation code.

microsoft-learn

~/.copilot/mcp-config.json (user scope)

Serves official Microsoft documentation search, full page fetch, and code samples through a streamable HTTP endpoint.

  • Pulling the current WinUI 3 x:Bind guidance before changing a XAML binding.
  • Fetching a complete Microsoft Learn page when a search result is truncated.
  • Retrieving an official code sample when the work touches Windows App SDK or FluentValidation APIs.
How it is configured
An HTTP server registered in the user profile at https://learn.microsoft.com/api/mcp, with all tools enabled.
Boundaries
Documentation only. It does not inspect the local codebase or resolve repository symbols; pair it with Serena for repo-grounded answers.
Search Microsoft Learn for WinUI 3 x:Bind UpdateSourceTrigger best practices,
then fetch the top page in full before I update the settings XAML.

speckit-hook

.github/hooks/speckit.json

Journals two agent lifecycle events to the Spec-Kit companion so the workflow tracks prompt submission and stop events.

  • Recording each submitted prompt with speckit.companion.on-prompt so the companion can attach context.
  • Recording the end of a turn with speckit.companion.on-stop.
  • Keeping the companion's event log in step with the chat without manual bookkeeping.
What it contains
Version 1 with two hooks. userPromptSubmitted runs python .specify/events.py speckit.companion.on-prompt user_prompt_submit 10 additionalContext, and agentStop runs python .specify/events.py speckit.companion.on-stop stop 10. Each entry carries a 15-second timeout and a __speckit_event__ flag.
Boundaries
Fires event journaling only. It does not run tests, write specs, or alter the repository itself.
Before submitting, check .github/hooks/speckit.json to confirm both event
hooks point at .specify/events.py and that the on-prompt and on-stop event names
match the companion commands.

dotnet-plugin-lsp

dotnet@0.2.5

The C# language server the dotnet plugin registers, owning diagnostics, hover types, and go-to-definition for the editor.

  • Seeing compiler diagnostics in a file before running a full build.
  • Reading the inferred type at a position with hover when a variable's type is unclear.
  • Jumping to the definition of a type or method from its call site.
How it is configured
Registered by the dotnet plugin via dnx roslyn-language-server --prerelease --stdio --daemon-mode --autoLoadProjects.
Boundaries
Reads and reports; it does not rewrite symbols across the codebase. Use Serena for symbol-level edits and this server for the diagnostic view.
Run diagnostics for Module_Receiving/Data/Dao_ReceivingLine.cs with the dotnet
language server and list every error with its line before I start editing.

Two C# language servers, one job each

QuestionUseWhy
Find, read, or rewrite a symbol Serena Symbol-level tools return one definition instead of a whole file.
See diagnostics, hover types, or go to definition The dotnet plugin language server Serena exposes symbol editing, not a full diagnostics stream.
Memory is tight Drop the dotnet plugin language server first Serena carries the daily editing workflow, so it stays.

Choosing between them. Reach for Serena when you need to read or change a symbol, and the dotnet language server when you need the diagnostic truth of the current buffer. Playwright and Microsoft Learn are web and documentation reach, not this desktop app's runtime, so leave them aside unless a web target or an official reference is actually in play.
