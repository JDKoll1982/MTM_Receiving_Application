Chapter 02

C# and .NET development

Building and fixing the application itself: routing to the narrowest C# specialist, behavior-preserving refactors, MSBuild diagnosis, local SDKs, async and best-practice guidance, and the test-framework skills. The stack is WinUI 3 on net10.0-windows10.0.22621.0 with the Windows App SDK, MediatR 14, FluentValidation 12, Serilog, OpenTelemetry, Mapster, and CommunityToolkit.Mvvm, plus Roslynator analyzers and CSharpier formatting.

The MVVM flow here is always View → ViewModel → Service → DAO. For the database end of that chain — MySQL 5.7 stored procedures and the read-only Infor Visual SQL Server — see the database chapter.

Boundaries
Routes and answers questions. It does not perform the refactor or build fix it hands off.

csharp-refactoring

dotnet@0.2.5

Performs behavior-preserving refactors — renames, method extraction, inlining, and nullability changes — while keeping any behavior-changing part separate.

  • Renaming a DAO method across Module_Receiving/ and its tests without breaking the Model_Dao_Result callers.
  • Splitting a nullable-annotation sweep from the behavior fix it was accidentally bundled with.
  • Extracting duplicated load-and-logic code in a Service into a private helper with no change to output.
Prerequisites
A compiling baseline — dotnet build MTM_Receiving_Application.slnx — so the refactor can be verified green.
Boundaries
Refactors only. It declines the behavior-changing part of a mixed request rather than folding it in.
Use the csharp-refactoring skill to rename Dao_ReceivingLine.GetByLoadAsync
to GetLinesByLoadAsync everywhere, including MTM_Receiving_Application.Tests. Keep
behavior identical and report any call site you cannot safely update.
