Chapter 04

WinUI 3 and the Windows platform

How this application runs on Windows: the WinUI 3 / Windows App SDK 2.4.0 stack behind the repo, the skills and agents that review, build, package, and test it, and the two repo-local skills that keep the agent setup and the MainWindow footer in shape.

Everything here assumes the repo's platform facts: net10.0-windows10.0.22621.0, UseWinUI=true, WindowsPackageType=None, XAML with x:Bind only, and the MVVM View→ViewModel→Service→DAO layering with no business logic in .xaml.cs.

winui-code-review

winui@0.8.0

Reviews WinUI 3 XAML and bindings against this repo's rules: x:Bind only, no runtime {Binding}, MVVM layering, and no business logic in code-behind.

  • Reviewing a changed view in Module_Receiving/Views/ for a stray runtime {Binding} before merging.
  • Verifying a new Module_Dunnage/ view keeps its code-behind empty and its x:Bind modes correct.
  • Confirming an edit did not push business logic into MainWindow.xaml.cs.
Prerequisites
The XAML and ViewModel to review, plus the MVVM rules in .github/copilot-instructions.md.
Boundaries
Reviews XAML, binding, and layering only. It is not a general C# logic reviewer and will not flag service or DAO bugs.
Use the winui-code-review skill on
Module_Dunnage/Views/View_Dunnage_WorkflowView.xaml and its ViewModel. Confirm x:Bind only
(no runtime {Binding}), no business logic in the .xaml.cs, and that the view calls only the
ViewModel. List each violation with file and line.

Repo-local skills

Two repo-owned skills are relevant here but live in the repo assets chapter so they are documented once: plan-mainwindowbuttonrevamp, which plans the MainWindow button revamp, and agent-performance-audit, which audits this agent setup for accuracy, speed, and token cost.

Reading order. Run winui-code-review on every XAML change, winui-dev for feature work, and winapp for packaging and UI automation. Reach for winui-ui-testing when a flow needs automated UI proof, and keep the two repo skills — plan-mainwindowbuttonrevamp and agent-performance-audit — for planning and agent hygiene, not implementation.
