Chapter 12

Repo skills, agents, and prompts

Indexing the automation assets that ship inside the repository itself: the 37 skills under .github/Skills, the three non-speckit agents under .github/agents, and the 82-entry prompt library under .github/prompts.

The speckit.* agents and their workflows are documented in the spec-driven chapter; here only the thin wrappers and stubs that make those commands discoverable from the skill and prompt palettes are listed.

Repo skills

agent-performance-audit

.github/Skills/

Audits your own agent setup for accuracy, speed, token, and consistency gains, gets per-item approval, then exports one repo-agnostic repo-performance-optimizer.md prompt.

  • Finding verified ways to improve your own accuracy, speed, token use, and consistency in this environment.
  • Turning only the improvements you approve into one reusable prompt you can paste into any repository.

/agent-performance-audit

Repo agents

MTM Module Improvement Auditor

.github/agents/

Audits a selected MTM module for performance, database interaction, end-user workflow friction, and UI design improvements without making code changes by default.

  • Running a no-code audit of a module before a refactor to surface the changes actually worth making.
  • Reviewing how a module touches MySQL or the read-only SQL Server ERP without writing to either.
  • Finding end-user workflow friction and UI rough edges in an existing screen.
Prerequisites
None beyond the plugin. The agent reads the module in place rather than accepting a description of it.
Boundaries
Reports findings by default; it does not edit code unless you explicitly ask it to.
Use the MTM Module Improvement Auditor on Module_Dunnage. Review performance,
database interaction, end-user workflow friction, and UI design, and list improvements
ranked by impact without editing any files.

Prompt Builder

.github/agents/

Expert prompt engineering and validation system for creating high-quality prompts, from microsoft/edge-ai.

  • Turning a rough task description into a complete prompt with role, context, and output format.
  • Validating an existing prompt for ambiguity before it drives a coding session.
  • Refining a reusable prompt so another agent can execute it without rediscovering the repository.
Prerequisites
None. It is a reasoning and authoring workflow rather than a code generator.
Boundaries
Produces and validates prompt text; it does not apply repository changes or run code.
Use the Prompt Builder agent to turn my rough note about adding a receiving
analytics tab into a complete, repo-grounded prompt with role, constraints, output
format, and an ordered task list.

WinUI 3 Expert

.github/agents/

Expert agent for WinUI 3 and Windows App SDK development that prevents common UWP-to-WinUI 3 API mistakes and guides XAML controls, MVVM patterns, windowing, threading, app lifecycle, dialogs, and deployment for desktop Windows apps.

  • Catching UWP APIs that no longer apply when adding a WinUI 3 view to a module.
  • Choosing the correct WinUI 3 control or dialog pattern for a new screen.
  • Guiding windowing, threading, and app-lifecycle decisions for desktop deployment.
Prerequisites
None. It leans on Microsoft Learn search for authoritative API details.
Boundaries
Advises and writes WinUI 3 code; it does not touch the MySQL or SQL Server data layers.
Use the WinUI 3 Expert agent to review my new receiving workflow page XAML and
code-behind for UWP-isms, and fix any x:Bind or dialog pattern that does not follow
WinUI 3 conventions.

How they differ. Skills are slash-command wrappers, agents are reusable roles with their own context, and prompts are self-contained task templates. The speckit family appears three times — as skills, as agents (documented in the spec-driven chapter), and as prompt stubs — because each surface registers the same workflow in a different way. The prompt stub whose name collides with a speckit skill is disambiguated by prefixing its group (root- or speckit-) in the entry id.
