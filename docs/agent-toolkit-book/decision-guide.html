Which tool when

Overlapping tooling is the most common failure mode in a set this size. Each row states a default, the reason, and the condition under which the other option wins. Every tool named here links to its entry.

Code intelligence

Question Default Why Use the other when
Find, read, or rewrite a symbol Serena Symbol-level tools return one definition instead of a whole file, which matters across 300+ C# files. You need diagnostics or go-to-definition, so use the dotnet plugin language server.
See warnings, errors, or inferred types dotnet plugin LSP It owns the diagnostics stream; Serena exposes editing, not a problem list. LSP memory is tight. Drop the dotnet plugin server first and keep Serena, because Serena carries the daily editing workflow.
A refactor that crosses many files refactor-plan It produces a plan and waits for confirmation before any file changes. The change is a pure rename in one project, so just run a language-server rename.

Windows packaging and setup

Question Default Why Use the other when
Packaging a WinUI 3 app winui-packaging It knows the WinUI template, Native AOT, and self-contained deployment. The target is not WinUI, so use winapp-package.
Setting up WinUI prerequisites winui-setup It owns the WinUI-specific chain including Developer Mode. You only need SDK init or restore on a non-WinUI project, so use winapp-setup.
Automated UI testing winui-ui-testing This app is WinUI 3, and that harness is written for it. You are automating a WPF, WinForms, or Electron target, so use winapp-ui-automation.
Finding the right Windows API or XAML winapp-find-api and winapp-find-ui They answer a single lookup rather than requiring you to describe a whole app. You need design or layout guidance instead, so use winui-design.

Testing

Question Default Why Use the other when
Running tests dotnet test MTM_Receiving_Application.Tests/MTM_Receiving_Application.Tests.csproj It is the documented command for this repo and needs no skill to be loaded. You need the correct filter syntax, TRX output, or crash diagnostics, so use run-tests.
Writing new tests This repo's own rules: xUnit, FluentAssertions, MethodName_ShouldResult_WhenCondition, IAsyncLifetime, TEST- prefixed data House conventions beat generic advice; the plugin skills do not know this repo's naming or fixture rules. You want a broad audit or repair pipeline, so use code-testing and let it apply the house rules you supply.
Deciding whether tests are good assertion-quality Weak assertions are the most common real defect in an existing suite. You want a full severity-ranked audit, so use test-anti-patterns.
Knowing what is untested find-untested-sources It pairs sources to tests structurally rather than guessing from coverage. You have a real coverage report to interpret, so use coverage-analysis.

Spec work

Question Default Why Use the other when
Building one feature speckit.specify then plan, tasks, implement Each step produces an artifact you can review before the next one starts. You want the whole pipeline hands-off, so use speckit.companion.auto.
Deciding whether an idea is worth building speckit.assess.intake then research, define, shape, decide It produces a go or kill verdict before any spec exists. The decision is already made, so start at speckit.specify.
Checking a run actually completed speckit.companion.doctor It reads the run journal rather than the prose, so it catches steps that closed having verified nothing. You only want the current position, so use speckit.companion.status.

Documents and diagrams

Question Default Why Use the other when
Producing a documentation package project-documenter It discovers the stack first, so the diagrams and prose match the code. You only need one picture, so use drawio.
Handing a document to someone in Word md-to-docx It converts faithfully and needs no Office install. The Markdown itself is wrong, so fix the Markdown first; conversion only copies whatever it is given.
Exploring an architecture interactively diagram-viewer Clicking a node and asking about it beats reading a static image. You need a file to commit, so use drawio.

Security and dependencies

Question Default Why Use the other when
Reviewing your own change for vulnerabilities github-security It scopes findings to the session's diff, which is where new risk actually lands. You want to work the standing GitHub alerts instead, which the same canvas loads through fetchGhasFindings.
Dependency version drift dependabot-triage It reports checks, mergeability, and overlap before recommending a merge. The alert set is empty but you still want an upgrade, so use dotnet-upgrade.

The meta-rule. When two tools overlap and neither row covers it, prefer the one whose chapter matches the job you are doing, then prefer the narrower tool. A single-purpose skill gives a sharper answer than a general agent, and you can always escalate.
