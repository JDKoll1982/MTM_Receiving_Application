📊 Module

Reporting

Query, filter, and export receiving and dunnage history. Generate reports by date range, employee, part number, or PO — and optionally schedule reports to be emailed automatically.

Overview

The Reporting module reads from the transaction history tables built up by the Receiving and Dunnage modules. It is read-only — nothing you do in Reporting changes the underlying records.

Reports can be generated on-demand and viewed on screen, exported to Excel, or copied to the clipboard as tab-delimited text for pasting into spreadsheets or emails.

ℹ️
Data is live. Every report reflects transactions that have been committed to the database — there is no cache. A transaction saved a moment ago will appear in a fresh report immediately.

Receiving History Report

The most commonly used report. It queries receiving_history and displays every committed receiving transaction within the selected filters.

Available filters

  • Date range — required; limits results to the selected window
  • Part number — filter by one specific part
  • PO number — filter by a specific purchase order
  • Employee — filter to one employee's transactions
  • Department — filter to all employees in a department

Columns displayed

  • Transaction date and time
  • Part ID and description
  • PO number and line
  • Quantity received
  • Package type and weight
  • Heat / lot number
  • Employee name
  • Vendor name

Dunnage Report

Queries dunnage_history to summarize dunnage receipts. Useful for verifying what dunnage was returned or received over a period.

Available filters

  • Date range — required
  • Dunnage type — filter to a specific category
  • Part — filter to a specific dunnage part
  • PO number — for dunnage tied to a specific PO
  • Employee — who performed the receipt

Exporting & Copying

After generating a report you have two ways to take the data out of the app:

📥

Export to Excel

Generates an .xlsx file with all visible columns and rows. Saves to your Documents folder by default; a Save dialog lets you change the location.

📋

Copy to Clipboard

Copies all visible data as tab-delimited text. Paste directly into Excel, Google Sheets, or the body of an email.

ℹ️
Filters are respected when exporting. Only the rows matching your current filter set are included in exports. Clear all filters before exporting if you want the full result set.

Scheduled Reports

Scheduled reports run automatically at a configured interval and send the results to one or more email recipients. They are managed in Settings → Reporting → Scheduled Reports.

How to set up a scheduled report

  1. Go to Settings → Reporting.
  2. Click Add Scheduled Report.
  3. Select the report type (Receiving History or Dunnage).
  4. Configure the date window (e.g., "Previous 7 days" or "Previous month").
  5. Set the schedule frequency (Daily, Weekly, Monthly).
  6. Add recipient email addresses.
  7. Save the schedule.
⚠️
Requires Administrator access. Only Administrators can create or edit scheduled reports. Contact your administrator if you need a report added to the schedule.

Common Questions

My report shows no results — is something wrong?

First check your date range — the most common cause of empty results is a date window that doesn't include any transactions. Also confirm that any secondary filters (part number, employee) match data that actually exists in the date range.

The Excel export has the wrong date format — how do I fix it?

The export writes dates in ISO format (YYYY-MM-DD HH:MM:SS). If Excel displays them as numbers, select the date columns, right-click, choose Format Cells, and apply a Date format.

Can I generate a report for all employees at once?

Yes. Leave the Employee filter blank and all employees will be included in the results. Use the Department filter to narrow to a group.

How often do scheduled reports run?

The schedule is set per-report in Settings. Common intervals are Daily (runs at a configured time), Weekly (runs on a selected day of the week), and Monthly. The exact run time is shown in the reporting_scheduled_reports table.
